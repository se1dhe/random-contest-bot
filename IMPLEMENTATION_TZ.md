# ТЗ на улучшения проекта

## 1. Ошибки в интерфейсе администратора
- Все действия админки должны показывать человеку видимую ошибку, а не только `console.error`.
- Для запросов создания, публикации, удаления, добавления каналов, розыгрыша и публикации результатов должен использоваться единый формат отображения `detail` от backend.
- UI должен поддерживать состояния `loading`, `success`, `error`.

## 2. Защита от гонок при регистрации
- Номер регистрации участника должен оставаться уникальным внутри конкурса при параллельных запросах.
- База должна гарантировать уникальность парой `(contest_id, registration_number)`.
- Сервис регистрации должен использовать блокировку конкурса на время вычисления следующего номера.

## 3. Единое логирование
- Все `print(...)` в критичном потоке публикации и результатов переводятся на `logger`.
- Логи должны содержать `contest_id`, `channel_id`, `user_id` там, где это возможно.

## 4. Smoke-check после запуска
- Должен существовать скрипт, который проверяет:
  - актуальную ревизию Alembic;
  - доступность web-сервиса;
  - доступность ngrok API;
  - наличие активного туннеля.

## 5. Предпросмотр публикации конкурса
- Админ должен иметь API для получения текста и кнопки будущего поста без отправки в канал.
- Предпросмотр должен содержать информацию о наличии изображения и ссылку кнопки.

## 6. Отложенная публикация
- Для конкурса должен храниться `publish_at`.
- Публикация должна планироваться через Redis по аналогии с авто-завершением.
- После рестарта бота отложенные публикации должны восстанавливаться.

## 7. Черновик результатов
- После розыгрыша должен существовать серверный предпросмотр результатов до публикации в канал.
- Админ должен получать список победителей и итоговый текст сообщения.

## 8. История действий администратора
- Нужно хранить действия администратора в отдельной таблице.
- Минимальные события:
  - создание/удаление конкурса;
  - публикация/отложенная публикация/перепубликация;
  - розыгрыш;
  - экспорт участников;
  - создание/удаление каналов.

## 9. Повторная публикация и обновление поста
- Для активного конкурса должны поддерживаться:
  - повторная публикация нового поста;
  - обновление существующего поста по `message_id`.

## 10. Экспорт участников
- Для конкурса нужен CSV-экспорт участников.
- Минимальные поля: номер регистрации, `user_id`, `username`, `first_name`, `last_name`, дата регистрации, `activity_score`.

## 11. Антидубликаты каналов
- Нельзя позволять использовать основной канал как спонсорский.
- Нельзя позволять повторять один и тот же спонсорский канал несколько раз.
- Backend должен возвращать понятную ошибку, UI должен её показывать.
